# Architecture

ConciergeClock follows the same structure as its siblings (PrepPilot, FocusFound, FotoPhilter):
a thin SwiftUI app shell over local Swift packages, with all persistence in one SQLite database.

```
ConciergeClock.xcodeproj         Single app target (iOS 26), folder-synced (Xcode 26)
ConciergeClock/                  App shell (SwiftUI, Swift 5 mode + complete strict concurrency)
  App/                           Entry point, AppModel (composition root), RootView (4 tabs +
                                 branded top bar), LaunchView (animated butler), ConciergeStyle
  Features/
    Alarms/                      Alarms tab (list; editor and AlarmKit in Phase 1b)
    Concierge/                   Concierge tab (the butler, next alarm, offline AI status)
    Sounds/                      Sounds tab (Phase 4)
    Trends/                      Trends tab (wake score explained; charts and Advisor in Phase 5)
    Settings/                    Settings, Your Concierge, Snooze, Mornings, Backup & Export, About
    OfflineAI/                   Offline AI screen, "Start here" card, setup guide (shared design)
  Services/                      SettingsStore, ModelService (Gemma), BackupService, Haptics
  Localization/                  Localizer (11 languages, RTL), Localizer+App (enum names)
  Components/                    Shared small views
  <lang>.lproj/                  Generated by tools/generate_strings.py — never edit by hand
Packages/
  ConciergeKit/                  Everything that is not UI
    ConciergeCore                Foundation only: AppSettings, Persona (name, accent, tone,
                                 length, language), Alarm, WakeEvent, WakeScore, Recommendation,
                                 BackupPayload + BackupMigrator, CSVExport, TextGenerating
    ConciergeData                GRDB: AppDatabase, Migrations, AlarmStore, WakeLogStore,
                                 RecommendationStore, BackupStore
  GGSBrand/                      Shared Greater Good brand UI (+ ButlerMark.swift, additive)
  GGSModelKit/                   Shared offline AI: model catalog, download, Gemma engine, guide
  LiteRTLM/                      Google's LiteRT-LM Swift wrapper (vendored, Apache 2.0)
Config/                          Info.plist additions (backup file type), entitlements
Design/                          Butler mark and app icon SVG/PNG sources
tools/                           generate_strings.py, generate_icons.py, butler_geometry.py,
                                 translations/<lang>.txt
docs/                            This file, decisions, data schema, roadmap, offline AI guide
```

## Principles in code

| Principle | Where it lives |
|---|---|
| One-time purchase, no accounts | No StoreKit, no login, no server code anywhere. |
| 100% local, never purged | `AppDirectories.applicationSupport` (never `Caches/`); one SQLite file via GRDB. |
| Offline | No network code except `GGSModelCore.ModelDownloader` (user-started model download). |
| Zero telemetry | No analytics SDKs; `PrivacyInfo.xcprivacy` declares no collected data. Wake log stores times and counts only. |
| Deterministic first | Every feature works with rules alone; Gemma (via `TextGenerating`) only ranks importance and varies wording. Times, titles and counts never come from the model. |
| Portability | `.conciergeclock` JSON backups and CSV exports, both versioned (`schemaVersion`); `BackupMigrator` upgrades old files; `docs/DATA_SCHEMA.md` is the contract. |

## Data flow

- `AppModel` owns the database and services and is injected with `.environment(model)`.
- `SettingsStore` holds `AppSettings` and writes every change to the `keyValue` table.
- `AlarmStore.observeAlarms()` and `WakeLogStore.observeEvents()` are GRDB `ValueObservation`s;
  `AppModel` mirrors them into observable properties for the views.
- Changing the wake score rules re-scores the whole wake log in the background.
- Backups: `BackupStore.exportPayload` reads everything in one transaction →
  `BackupPayload.encoded()` → share sheet or the chosen folder. Restore: file → `BackupMigrator`
  → integrity check → confirmation → `BackupStore.replaceAll` (one transaction).

## How the alarm will work (Phases 1b–3)

1. **AlarmKit** schedules every alarm: it rings through silent mode and Focus, on the Lock
   Screen and in the Dynamic Island, with Stop / Snooze and a "Brief me" button that opens the
   app. This is the safety net and always on.
2. **Nightstand Mode** (on the charger at bedtime): the app keeps running with the ambient sound,
   prepares the briefing (and lets Gemma rank importance) about 10 minutes before the alarm, then
   speaks, listens for "snooze 10 minutes" / "I'm awake" / "mark it done", and logs the morning.
3. **Pre-recorded briefing:** the spoken briefing is rendered to a sound file and given to
   AlarmKit as the alarm sound, so it is heard even when the app was closed.

## Languages

`tools/translations/<lang>.txt` (`key | value`) is the source for all 11 languages.
`python3 tools/generate_strings.py` checks that every language has the same keys and placeholders
and that every key used in Swift exists, then writes `ConciergeClock/<lang>.lproj` and the shared
setup guide's strings in `Packages/GGSModelKit/Sources/GGSModelUI/Resources`. Strings shared with
the siblings (Settings basics, Offline AI, About Greater Good Software) were taken from PrepPilot.
